🎯 Project Goal

Students often struggle to find information in HUMG's training regulations because traditional keyword search fails when queries don't contain exact terms from the regulation text. This project builds a Dense Passage Retrieval system that understands semantic meaning — so asking "Nghỉ bao nhiêu buổi thì bị cấm thi?" (How many absences before being banned from exams?) returns the relevant regulation about exceeding 20% absences, even without matching keywords.

🏋️ Training Phase PhoBERT
  • Dual Encoder (shared weights)
  • In-Batch Negatives (B=64)
  • Mean Pooling → L2 Norm
  • Cross-Entropy on B×B matrix
  • Linear warmup + decay
  • Best val_loss checkpoint
🚀 Inference Phase FAISS
  • Encode passages → .npy embeddings
  • IndexFlatIP (exact search)
  • Query → encode → FAISS search
  • Top-K passages returned
  • passage_id_map.json for lookup
  • Interactive REPL interface

  • Recall@{1, 5, 10, 20}

  • Precision@K
  • Latency (ms/query)
  • DPR vs BM25 vs TF-IDF
  • Grid search for BM25 tuning
🧠 Dual Encoder Detail
// Encoding Architecture
Query → PhoBERT("vinai/phobert-base") → MeanPool(hidden, mask) → L2Norm → q_vec (768-d)
│
dot product → (B×B) scores
│
Passage → PhoBERT("vinai/phobert-base") → MeanPool(hidden, mask) → L2Norm → p_vec (768-d)

// Loss: CrossEntropy(scores, arange(B))
// Each query has 1 positive + (B-1) in-batch negatives
// Shared encoder → same weights for Q and P

📋 Key Design Decisions
🔗
Shared Encoder
Tied Q & P weights

Both query and passage encoders share the same PhoBERT weights, reducing model size by 50%. Trade-off: separate encoders could specialize better but require more data and memory.

📊
Mean Pooling
vs CLS Token

Uses attention-weighted mean pooling over all tokens instead of CLS token. More robust for passage retrieval as it captures information from the entire sequence.

🎯
In-Batch Negatives
Memory-efficient training

With batch size 64, each query gets 63 negative passages "for free" from other pairs in the same batch. No need for separate hard negative mining.

🧮
L2 Normalization
Cosine = Dot Product

All embeddings are L2-normalized, making inner product equivalent to cosine similarity. Enables using FAISS IndexFlatIP for exact cosine search.
